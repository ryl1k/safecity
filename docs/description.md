SafeCity

Карта й навігатор доступності для людей на кріслі колісному. Прокладає пішохідні маршрути в обхід непрохідних ділянок і чесно попереджає, коли доступного обходу немає.


Задача

Люди на кріслі колісному не можуть покластися на звичайні карти: ті прокладають маршрут «як для всіх» і ведуть через сходи, бордюри та вузькі тротуари, часто у глухий кут. SafeCity вирішує саме цю задачу, прокладаючи пішохідний маршрут, прохідний для крісла, доступними тротуарами та громадським транспортом.

Трек: Соціальні технології, інклюзія та доступність.

Коротко

Звичайні карти прокладають маршрут «як для всіх» і ведуть людину на кріслі через сходи та бордюри, часто у глухий кут. SafeCity вирішує саме це: не просто показує доступні місця, а рахує маршрут, прохідний для крісла, доступними тротуарами та громадським транспортом. Робочий MVP, запущений у Львові: понад тисячу точок доступності, жива покрокова навігація, розгорнутий у продакшні.


Ринок

Війна різко збільшила кількість людей з інвалідністю, лише за півтора року орієнтовно на 300 тисяч, тож потреба в доступному середовищі стала масовою. Держава запустила профінансовану Національну стратегію безбар'єрності до 2030 року й уже краудсорсить дані через «Мапу безбар'єрності», тобто попит, політика й модель даних підтверджені. Конкуренти (Wheelmap, Google/Apple Maps, Dostupno.UA) спиняються на питанні «чи доступне місце»; ніхто не прокладає пішохідний маршрут для крісла. Монетизація: freemium плюс преміум 200 грн/міс (2 000 грн/рік), а головний B2B-гачок це дані попиту, яких не дає ніхто, коли заклад бачить, скільки людей на кріслі шукали його, але не змогли дістатися.


Технології та алгоритми

Архітектура. Веб на Next.js і мобільний клієнт звертаються до єдиного Go API, який стоїть перед Supabase (PostgreSQL + PostGIS + pgRouting). Безпека даних через RLS: кожен запит виконується в транзакції під роллю користувача з його JWT-claims, тож політики Postgres застосовуються автоматично. Пул до бази через transaction-mode pooler, що дозволяє багатьом клієнтам мультиплексуватися на кілька бекендів.

Маршрутизація для крісла. Пішохідним рушієм виступає OpenRouteService. Ключова логіка живе на нашому боці: з непрохідних сегментів будуються буферизовані зони уникнення (avoid_polygons), і рушій обходить їх. Окремо реалізовано чесний детектор, коли маршрут іде не по червоному, а вздовж нього (проїзна частина проти тротуару, різниця близько десяти метрів): рахується частка сегмента в межах п'ятнадцяти метрів від лінії маршруту, і якщо вона перевищує поріг, користувача попереджають. Маршрути pgRouting, що перетинають червоні ділянки, відкидаються на користь ORS. Для поїздок є транзитний режим на базі Transitous (MOTIS), де кожен відрізок отримує позначку доступності з GTFS-прапорців.

Рейтинг і дані. Рівень доступності сегмента тротуару рахується в SQL за принципом «гірше з двох» (тип покриття проти рівності), щоб рейтинг не завищувався. Рівень доступності місця це зважена функція від його ознак (вхід, двері, пандус), з рівнями низький, середній, високий замість вигаданих відсотків. Дані зводяться з трьох джерел (державна «Мапа безбар'єрності», OpenStreetMap, повідомлення громади) з дедуплікацією; там, де даних немає, рівень чесно позначається як невідомо.


Стан

Працюють: вебзастосунок з mobile-first дизайном, маршрутизація доступними тротуарами й транспортом, жива навігація з голосом, панель аналітики для бізнесу, консоль модерації. Розгорнутий у продакшні (веб на Vercel, Go API на Render, база на Supabase), дані з трьох джерел наживо. Нативні мобільні застосунки в розробці.


Родмапа

Реліз нативних застосунків для iOS та Android на основі готового mobile-first дизайну. Розширення на нові міста. Монетизація для бізнесу та сервіс верифікації закладів. Муніципальні контракти й аналітичні дашборди для міст. Публічний API та ліцензування даних.
